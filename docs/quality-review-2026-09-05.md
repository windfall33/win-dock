## 1. 实物效果（以实拍为证）

### 1.1 改造前后对比（同一机器、同一工具链）

| 对比点 | 改造前 `full-idle.png` | 现状 `w2-full.png` / `w2-fisheye.png` |
| --- | --- | --- |
| 深色图标（OpenAI/GitHub/终端/K） | 融进深色玻璃，几乎不可见 | 统一浅色 squircle 底板，全部清晰可辨 |
| 图标观感 | Windows 原始形状图标，尺寸参差 | 统一圆角容器 + 内缩 padding，尺寸齐整，最接近 macOS 的一步 |
| 倒影 | 无 | 玻璃板下缘渐隐倒影（实拍调参 0.15→0.32 才在深色玻璃上可见） |
| 鱼眼态 | 图标穿出玻璃板顶 | 面板随放大增高，图标完全在板内；放大曲线连续挤压更接近 mac 手感 |
| 运行指示点 | 4px 无描边，实拍几乎不可见 | 5.5px + 白描边 + 投影，可辨 |

### 1.2 实物仍可见的差距（按显眼程度排序）

1. **玻璃材质是「暗色磨砂」而非「亮灰玻璃」**。macOS 的 Dock 底座是亮色半透明 + 顶部锐利高光 + 底缘收暗，光会「透过」它；我们的版本整体偏暗偏平（深色主题下尤甚）。顶部高光 0.72 已加，但对比真机仍差一层。这是材质引擎差距，追加轮的玻璃层次已经是无系统合成器前提下的合理上限。
2. **「板中板」**。所有图标一律加浅色底板后，本身就是彩色 squircle 美术的图标（QQ、千问、豆包）看起来是「彩板外面再套白板」，细看与 macOS（底板即美术本身）可辨。这是 Windows 图标源的固有限制下的正确取舍，无解，只能接受。
3. **放大时图标边缘偏软**。桥接提取的图标分辨率有限，鱼眼放到 ~1.8× 时边缘发虚；macOS 图标是高分辨率美术资产。可尝试让桥接改取 `SHGetImageList` 大尺寸 / `IExtractImage` 256px 路线，属于中等成本的图标管线改造。
4. **状态延迟**。应用启动/关闭到 Dock 反映，最长 ~1.4s（焦点变化场景已用近似方案压到 ~250ms）。macOS 是事件驱动、瞬时。日常可忍，对比真机一用便知。
5. **通知角标仍是「猜」**。靠窗口标题正则，微信类托盘应用最小化后即失效；macOS 是系统级通知推送。

## 2. 代码质量

### 2.1 做得好的（有证据）

- **分层干净**：`bridge.ps1`（Win32 原子操作）→ `native.js`（NDJSON 协议 + 守护）→ `core/*`（纯函数）→ `main.js`（合成 + IPC）→ `renderer`（DOM）。依赖方向单一，没有反向渗透。
- **纯函数下沉是正确的架构动作**：`core/snapshot.js`、`core/pin-app.js` 用依赖注入把状态合成与固定逻辑从 Electron 副作用里剥离，注释明确写了「提取动机」和「依赖契约」，可在 node:test 里整段验证。这是给 main.js 继续瘦身铺路的正确姿势。
- **熔断器质量高**（native.js:47-69）：指数退避 1.5s→60s 封顶、稳定运行 10s 重置序列、崩溃时 `failAll` 清挂起请求、`onReady` 供主进程重放副作用。边界都想到了。
- **实拍驱动的调参文化**：CSS/JS 注释里保留着调参证据链（倒影 0.15 不可见→0.32；指示点 4px 不可见→5.5px+描边；icon-plate.js 两次返工的根因复盘）。半年后回看也能知道「为什么是这个数」。
- **安全细节到位**：`reveal` 剥引号防注入、桥接 UTF-8 强制、asar 路径重写、`before-quit` 清理定时器与工作区恢复。
- **测试从 36 → 57 全过**，且覆盖了 badges/minimized/recent/pin-app/snapshot 这些真实业务分支，不是凑数的测试。

### 2.2 不足与风险（按优先级）

1. **renderer.js 1966 行仍是最大单体**：布局、鱼眼、拖拽、菜单、Stack、预览、弹簧全在一个文件。已开始下沉（genie/launchpad/expose/icon-plate 已拆出），下一步应按同模式拆「鱼眼引擎」和「拖拽状态机」。
2. **编排层零覆盖**：`pollOnce` / `checkOcclusion` / `applyWorkarea` / `handleInvoke`（~295 行 switch）没有任何测试。状态合成已有回归网，但「把状态送到渲染层」的编排逻辑改动仍靠真机验证。
3. **`quit-app` 的 taskkill 无 `/F`**（main.js:699-711）：按窗口 PID 逐个优雅退出（发 WM_CLOSE），方向正确；但个别应用 WM_CLOSE 会弹「是否保存」对话框导致进程不退， Dock 端无超时升级为强杀的兜底。
4. **`processes-running` 用 `Get-Process` 按名匹配**（bridge.ps1:638-652）：固定项是全路径、查询按 basename，同名不同路径的应用会互相「点亮」运行状态。低频但存在。
5. **IconCache.logSafe 是 noop 桩**（native.js:191）：图标拉取失败被静默吞掉，排查「图标缺失」类问题会没有日志线索。
6. **常驻内存 ~517MB**（4×electron ≈402MB + 桥接 115MB，空闲 CPU≈0）：对常驻组件偏高但与功能量匹配；关顶栏可省 ~40MB，已提供开关。
